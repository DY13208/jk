# 可靠性完善与测试报告（2026-10-10）

本次保留 Crawl4AI、APScheduler、FastAPI、SQLite 和 Tabler，直接完善现有代码。

## 已修复

- 访问被拒绝后，修改通知或网站名称仍保留暂停原因；只有明确重新启用才清除原因。
- 新采集快照必须带 `complete: true`，同时通过原有分页、总数、重复 ID 和关键字段校验。旧数据导入继续兼容历史格式。
- SMTP 就绪提示复用实际发送配置校验，错误端口、加密方式、发件邮箱或账号密码组合不会显示已配置。
- 普通通知进程不再回收 Agent Mail 工作进程领取的任务，避免误报发送结果不确定。普通通知中断判定窗口调整为 120 秒。
- 总览分别显示待发送/发送中数量和暂停/需人工核对数量。
- 执行日志页增加备份列表、文件大小和下载入口；下载接口限制备份目录及文件名，拒绝符号链接和路径穿越。
- 更新前端资源版本，刷新即可加载最新代码。

## 操作

访问 http://127.0.0.1:8080/#logs 查看备份。顶部“数据备份”生成 SQLite 一致性备份，再从列表下载。
下载接口沿用后台登录保护。备份包含网站设置和历史记录，请保存在自己的存储中。
本次未添加在线覆盖数据库的恢复按钮，以免误操作覆盖正在运行的数据。
