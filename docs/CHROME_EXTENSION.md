# 日常 Chrome 扩展接入

这条路线在你日常使用、能正常加载网站的 Chrome 会话中新开采集标签页，不再由 Playwright 另起浏览器。它不会读取或导出 Cookie，也不需要开启调试端口。

## 本机已经准备好的安装步骤

1. 在平时能打开 Lecomte 的 Chrome 中，地址栏输入 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 **`D:\jk\chrome-extension`**。
4. 点击工具栏的扩展图标，打开“商品监控 · 日常 Chrome 采集”。
5. 选择 Lecomte，点击 **“完整采集测试（不写入快照）”**。

该测试会在当前 Chrome 会话内新开商品目录标签页，逐次点击“加载更多”；完成后关闭扩展创建的标签页。它不复用或关闭你已有的购物标签页，不修改购物车。

看到“测试通过：N 件 / P 页，未发送通知”后，才到后台启用该网站，进行真实快照采集。首次测试不是正式基线，不会覆盖现有历史快照。

Chrome 需要由用户亲自完成加载扩展的操作。本项目没有远程安装扩展或修改日常 Chrome 配置。

## 在另一台电脑重新准备

```powershell
cd D:\jk
docker compose up -d --build
python scripts/prepare_extension.py
```

脚本生成 `chrome-extension/config.local.json`，内容为本机后台地址和扩展专用令牌。这个文件不要发给别人，不会进入 Git 或源码包。删除数据目录或更换令牌后，重新运行脚本，再在 Chrome 扩展页点击刷新。

## 后台设置

网站设置的采集运行位置选择“日常 Chrome 扩展”，分页方式选择“页面内加载更多”。现有 Lecomte 已配置为此模式并保持暂停，通知仍关闭，等待日常 Chrome 的实测通过。

配置对应：

```json
{"execution_mode":"extension","pagination_mode":"load_more","page_delay":3}
```

后台继续使用 APScheduler 每 15 分钟调度，扩展通过 Chrome alarms 每 30 秒检查是否有任务。浏览器关闭、电脑睡眠或系统限流时不能保证准点；它不是独立服务器。Chrome alarms 行为见官方文档：https://developer.chrome.com/docs/extensions/reference/api/alarms 。

扩展仅申请本机后台和 `www.lecomte-alpirando.be` 的访问权限，没有 Cookie、debugger、webRequest、全部标签页读取或全站权限。当前仅提供已验证的 Lecomte/Odoo 扩展适配规则；其他站点继续使用现有独立适配器，后续扩展新域名时需明确增加授权及规则。

## 复用与校验

扩展只负责页面操作和商品卡片/分页 DOM 传输，DOM 中的脚本、按钮、图片、CSRF 输入等非采集字段会被移除。后台仍通过 Crawl4AI 的 JsonCssExtractionStrategy 和原有 Odoo 稳定 ID 规则提取商品，再进入原有 SQLite 比对事务。

每一批累计商品都要校验：页码连续、总数及页数稳定、商品数增长、已有 ID 不丢失、不重复、既有价格不在同轮变化，最终数量等于站点声明数量。残缺数据不会提交，90 件中下架 2 件并新增 2 件仍能识别全部四个事件。

扩展与原本机 Python 进程使用独立令牌和独立任务筛选，不能互相领取任务。任务超时、重复或凭据不符的结果会被拒绝；传输失败仅重交已有结果，不盲目重跑采集。

## 验收范围

已完成后台接口、DOM 提取及本地有界面 Chrome 的动态加载自动测试，包括敏感输入剔除、只读测试不写入快照、90→90 差异识别和失败保护。

本轮完整测试为 156 passed、2 skipped、1 warning，98.01 秒；扩展与采集接口专项为 18 passed。跳过项为旧 changedetection 集成和 Windows 原生专属测试；Windows 原生测试在上一轮已单独运行通过。警告为 Starlette 测试依赖弃用提示。

**尚待你在日常 Chrome 加载扩展后，验证真实 Lecomte 全目录；不能把代码测试通过表述为真实网站监控已恢复。** 验证通过后还需连续运行观察，确认长期访问稳定。

## 1.0.2 标签页自动清理（2026-10-16）

- 按任务创建的标签页 ID 记录归属。采集成功或失败后都会关闭该页，即使跳到商品详情、其他路径或其他网站，或无法读取当前 URL。
- 不扫描或关闭用户原来打开的标签页；正在执行的任务不会被遗留页清理打断。
- 后台断线也会清理中断任务的标签页，关闭失败保留记录并在后续检查重试。弹窗“清理遗留采集页”也使用相同归属记录。

更新方法：等待当前采集结束，在日常 Chrome 的 `chrome://extensions` 找到本扩展，点击刷新图标，版本应为 **1.0.2**。仅刷新监控后台网页不会更新扩展。

Chrome 重新加载扩展会清空扩展的会话存储。此前已丢失归属记录的旧标签页需要手动关闭一次；后续任务由新版本自动关闭。

回归命令：`node tests/extension_worker.test.cjs`。覆盖任务页重定向、URL 不可读、成功及失败结束清理、用户标签页不受影响、关闭失败重试、后台断线、活动任务保护、旧记录迁移和结果重交。
